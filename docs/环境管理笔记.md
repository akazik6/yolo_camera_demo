# 环境管理笔记（Conda）

## 1. 为什么需要独立环境

- **依赖隔离**：不同项目依赖的 torch / numpy 版本往往不同，装在全局环境里只能保留一份，升级一个项目就会破坏另一个项目。
- **可复现**：把环境导出成 `environment.yml`，换一台电脑可以原样重建，避免“我的电脑能跑”。
- **不污染系统**：项目环境可以随时删除重建，不会影响系统自带的 Python 和其他工具。
- **权限友好**：环境建在用户目录下，不需要管理员权限。

## 2. 常用命令

| 目的 | 命令 |
| --- | --- |
| 创建环境 | `conda create -n perception python=3.10 -y` |
| 激活环境 | `conda activate perception` |
| 退出环境 | `conda deactivate` |
| 查看所有环境 | `conda env list` |
| 查看当前环境的包 | `conda list` |
| 安装包 | `conda install numpy` / `pip install ultralytics` |
| 导出环境 | `conda env export > environment.yml` |
| 按文件恢复环境 | `conda env create -f environment.yml` |
| 删除环境 | `conda remove -n perception --all` |
| 清理缓存 | `conda clean -a` |

## 3. 三个问题

### 3.1 为什么不同项目要用独立环境

不同项目对同一个库的版本要求可能互相冲突。例如 A 项目依赖 PyTorch 1.13，B 项目要用 PyTorch 2.x 的新算子；装在同一个环境里只能保留一个版本，必然有一个项目跑不起来。独立环境让每个项目拥有自己的依赖集合，互不影响，也方便单独删除。

### 3.2 Python 或依赖版本不一致会怎样

- **二进制不兼容**：numpy 2.x 与旧版编译的扩展混用，容易出现 `numpy.core.multiarray failed to import` 一类报错。
- **API 变化**：库的大版本升级可能删除或重命名接口，旧代码直接 `AttributeError`。
- **行为变化**：默认参数、数值精度改变，程序不报错但结果不同，排查成本更高。
- **难以复现**：没有记录版本时，别人无法还原你的运行环境。

因此项目要固定依赖版本，并提交 `requirements.txt` / `environment.yml`。

### 3.3 Conda、uv、venv 的区别

| 维度 | Conda | uv | venv |
| --- | --- | --- | --- |
| 管理对象 | Python 解释器 + 二进制依赖 + Python 包 | Python 包（也能装 Python 版本） | 仅 Python 包 |
| 包来源 | conda 频道（conda-forge 等） | PyPI | PyPI |
| 非 Python 依赖 | 支持（CUDA、OpenCV 系统库等） | 不支持 | 不支持 |
| 速度 | 较慢 | 很快（Rust 实现） | 中等 |
| 锁文件 | `environment.yml`（不严格锁定） | `uv.lock` | `requirements.txt` |
| 适合场景 | 科学计算、深度学习、依赖复杂 | 新项目、CI、追求安装速度 | 临时隔离、标准库自带 |

本项目需要 PyTorch、OpenCV 等带二进制依赖的包，且任务要求使用 Conda，因此选择 Conda 创建 `perception` 环境。

## 4. 本次实践

```bash
conda create -n perception python=3.10 -y -c conda-forge --override-channels
conda activate perception
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple ultralytics
python -c "import torch, ultralytics; print(torch.__version__, ultralytics.__version__)"
```

> 新版 conda 使用默认频道前需要先接受服务条款，这里直接指定 `conda-forge` 频道绕过该步骤。
